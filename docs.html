How it connects
The browser calls GAS server functions via google.script.run. This only works when the page is served from the /exec deployment URL — never when the HTML file is opened directly from Drive.

Step 1 — Create a Google Spreadsheet

  1. 1

    Open Google Drive

    Go to drive.google.com → New → Google Sheets. Give it any name, e.g. Flash Cards.

  2. 2

    Note the Spreadsheet ID

    The URL looks like https://docs.google.com/spreadsheets/d/SPREADSHEET_ID/edit. You don't need to use this ID directly — just keep the sheet open.

Step 2 — Create the Apps Script Project

  1. 1

    Open Apps Script editor

    In your spreadsheet: Extensions → Apps Script. A new tab opens with the editor.

  2. 2

    Paste Code.gs

    Click the default file (usually Code.gs). Delete everything and paste the full contents of Code.gs.

  3. 3

    Create index.html

    Click + (New file) → HTML. Name it exactly index (no extension — GAS adds .html automatically). Delete everything and paste the full contents of index.html.

  4. 4

    Save both files

    Cmd/Ctrl+S or click the floppy disk icon. Both files must be saved before deploying.

Step 3 — Initialize the Sheet

  1. 1

    Run setupSheet()

    In the editor, select setupSheet from the function dropdown → click ▶ Run. Accept any permission dialogs (this only runs once).

  2. 2

    Verify the sheet

    Switch to your Spreadsheet. A tab named cards should appear with 14 purple header columns.

Important
If you skip setupSheet() and create the sheet manually, make sure all 14 column headers exist. Missing FSRS headers cause silent write failures. The app will auto-add any missing ones on first review, but it's cleaner to run setup first.

Step 4 — Deploy as Web App

  1. 1

    Click Deploy → New deployment

    In the Apps Script editor top-right: Deploy → New deployment.

  2. 2

    Configure settings

    Select type: Web app. Execute as: Me. Who has access: Only myself.

  3. 3

    Copy the /exec URL

    After deploy, copy the URL ending in /exec. Bookmark this on every device. This is the only URL the app works from.

Critical
Always use the /exec URL — never open index.html directly from Drive. google.script.run (the bridge between frontend and sheet) only works when the page is served by GAS. Opening the file directly gives a broken page that looks fine but never saves.
After code changes
Each time you edit anything in the apps script, a new deployment is required: New deployment (Deploy → New deployment) changes the URL each time; New version (Deploy → Manage deployments → Edit Version) reuses the same URL. Or use "Test deployments" during development — those always reflect the latest saved code.

Back Card Types

back_type = text

Plain text, whitespace preserved. Best for short definitions.

Prunus serrulata
Japanese flowering cherry.
Blooms ~2 weeks, late March to early April.

back_type = md

Standard Markdown rendered via marked.js. Supports headings, lists, bold, italic, tables, code, blockquotes, and image syntax.

## 桜 Cherry Blossom
- **Species:** *Prunus serrulata*
- **Season:** Late March – early April (Tokyo)
- Hanami (花見): tradition of picnicking under blooms

Review Session

Open the /exec URL. The home screen shows today's due count. Hit Start Review.

Each session goes through all cards due today in order (most overdue first, new cards last). A progress bar tracks completion. When all cards are rated, a summary screen shows totals.

Keyword Reveal Mechanic

When a card loads, the front shows only the title — no keyword pills are visible yet. Ghost placeholder pills show how many keywords exist.

Click ＋ Hint to reveal one keyword per click. The hint picker avoids revealing keywords you have already attempted in Spell Check (see below). Click ↩ Flip at any point to see the answer on the back.

The number of hints needed determines the suggested rating:

0 hints
Flipped without any hint
→ Easy (4)
1+ hints
At least one hint needed
→ Good (3)
>50%
More than half shown
→ Hard (2)
n / n
All keywords shown
→ Again (1)
1 / 1
Single keyword card
→ Rate manually

The suggested button is highlighted with a white outline. You can always override by clicking any other rating button.

Spell Check

Click ✎ Spell on the front card to enter spell-check mode. The ghost placeholder pills turn into text input fields — one per hidden keyword.

Type your guesses in any order, then click ✔ Check (or press Enter in any field). The app finds the best keyword match for each input using fuzzy matching (Levenshtein distance ≤ 2), so minor typos are forgiven. Inputs turn green for a match, red for no match.

Order doesn't matter
Keywords are matched globally across all inputs. You can type them in any order — the app assigns each input to the keyword it fits best.

✔ Check — evaluates all inputs and highlights results.
✕ Clear — clears all inputs and resets highlighting.
✎ Spell (toggle off) — exits spell mode and restores ghost pills, discarding inputs.

Hint interaction
When you click ＋ Hint while spell mode is active, the app picks a keyword that is unlike anything you have already typed (edit-distance > 2). This prevents hints from revealing words you have already attempted, keeping the challenge fair.

Already-revealed hint pills (shown in color) are not spell-check targets — only the remaining hidden slots are checked.

FSRS v5 Algorithm

FSRS v5 (Free Spaced Repetition Scheduler) is the algorithm used by Anki since 2023. It models memory using three variables:

VariableMeaningRange
Stability (S)Days until retrievability drops to 90%0.1 → ∞
Difficulty (D)Intrinsic card hardness1 → 10
Retrievability (R)Probability of recall right now0 → 1

Forgetting curve:

R(t, S) = (1 + 0.2346 × t / S)−0.5

At t = S days, R = 0.90 — that's the 90% retention target baked into the constants.

The W parameters (19 values) are the default from the open-spaced-repetition project. To personalize them, run fsrs-optimizer on your review log and replace the W array at the top of the <script> block in index.html.

Card States

StateValueMeaningNext interval
New 0 Never reviewed. Blank FSRS fields. Good/Easy→1+ days; Again/Hard→enters Learning (10 min / 1 h)
Learning 1 First few reviews. Building initial stability. Again→10 min, Hard→1 h, Good/Easy→graduates to Review
Review 2 Graduated. Scheduled by FSRS interval. Days–months based on stability
Relearning 3 Lapsed (rated Again while in Review). Relearning. Again→10 min, Hard→1 h, Good/Easy→back to Review

State is shown as a colored badge in the top-right of the front card face.

Common Issues

SymptomCauseFix
Sheet never updates after rating Page opened from Drive, not /exec URL Always use the deployment /exec URL
google.script.run is not defined Same as above Same fix — use the /exec URL
FSRS columns are blank after review Column headers missing from sheet Run setupSheet() once, or add missing headers manually. App auto-adds them on next review.
Card doesn't flip back between cards CSS .flipped class not removed Ensure loadCard() calls card3d.classList.remove('flipped')
Markdown not rendering marked.js CDN failed to load Check browser console; ensure CDN access. Fallback: self-host marked.min.js in a Drive-served script
Home screen shows 0 cards but sheet has cards Sheet name mismatch or no id column Sheet tab must be named exactly cards; every row must have a non-blank id
Redeploying after code changes has no effect GAS caches the previous deployment Deploy → New deployment (not "Manage deployments"). Old /exec URL stays valid but points to old version

Each time you edit Code.gs or index.html, a new deployment is required. Or use "Test deployments" during development — those always reflect the latest saved code.
